# Complete candidate and compatibility matrix — 14 November 2026

This is an audit decision register, **not an installation list**. All 138 inventory rows are present exactly once, in input order. Original owner aliases are preserved; corrected locations and evidence are in [the upstream register](ECOSYSTEM_UPSTREAM_EVIDENCE_2026-11-14.json). See [the architecture audit](ECOSYSTEM_ARCHITECTURE_AUDIT_2026-11-14.md) and [benchmarks/roadmap](ECOSYSTEM_IMPLEMENTATION_ROADMAP_2026-11-14.md).

**Counts:** KEEP EXISTING: 18; DEFER: 66; EXPERIMENT: 20; REJECT: 28; INTEGRATE: 6.

## Decision and evidence meanings

- **INTEGRATE:** justified future addition with an assigned phase and acceptance gate; nothing installed by this audit.
- **EXPERIMENT:** controlled comparison, default off; promotion requires demonstrated gain.
- **KEEP EXISTING:** retain already-used candidate or its existing official wrapper/transitive role, without upgrading or broadening permissions.
- **DEFER:** revisit only for an unmet use case in the appropriate later phase.
- **REJECT:** reject as an Immortility runtime dependency under this architecture; reference reading remains possible.

Every candidate's linked GitHub page and license/README section was requested on 14 November. Some web results are cached; the register records cache age. The original HomeAssistant/core URL failed; home-assistant/core was then inspected. A successful page fetch establishes neither ongoing maintenance nor safety. Exact latest commit dates, CVE clearance, Windows execution and release-level license closure are **not certified for all 138**. Current source/manifests were additionally checked for the shortlist; concrete incompatibilities are described in the architecture audit. License column is observed scope, not a blanket grant for weights, assets, plugins, bundled binaries or hosted plans.

## Resource and token profiles (all estimates, not measurements)

Every row maps to the full CPU/RAM/GPU/disk profile below. These are conservative planning envelopes, not publisher benchmarks or installed-size promises. All optional processes should use **zero additional process RAM/CPU/VRAM while disabled**; code/assets can still occupy disk. Dormant libraries add bundle/import cost where loaded.

| Profile | Typical active CPU and RAM estimate | GPU / VRAM estimate | Additional disk estimate | Runtime implications |
|---|---|---|---|---|
| U | UI work: <1–5 ms/frame target; +0–100 MB JS/render memory | 0–500 MB, scene/effects dependent | KB–50 MB selected assets/chunks | No background service; defer mounts, retain existing frame caps |
| P | Deterministic tool/dev job: 1–2 CPU cores, 30–300 MB | 0 | 10–500 MB dependencies; scanner DB can exceed 1 GB | Burst-only worker/CI; parser outputs bounded |
| D | Retrieval index: 1–2 cores while indexing; 50–500 MB plus corpus | 0 | 10–500 MB plus vectors/text | One writer, derived index; 100k × 384 × 4-byte vectors ≈147 MiB before overhead |
| E | LSP/embedding/memory: 1–4 cores; 200 MB–2 GB | CPU first, 0 VRAM; optional accelerator up to 2 GB | 0.1–3 GB code/models/index, corpus extra | LSP and Bun/PGLite vary widely; no model-extraction calls by default |
| V | Speech: 1–4 cores; 0.2–2 GB for small ASR/TTS | CPU baseline; GPU variant 0.3–3 GB | 0.1–4 GB engine/models, Torch env may be much larger | One active speech engine, unload policy; continuous mic is a separate opt-in |
| C | Windows driver: burst CPU; 50–300 MB plus target app | No ML VRAM; screenshot buffers extra | 10–300 MB binaries/libs | Interactive session, UIA first; OS app RAM excluded |
| B | Browser: 1–4 burst cores; 0.2–1.5 GB per active task | 0–500 MB rendering, no ML weights | 0.1–1.5 GB binaries/cache | Browser session single-owner; fallback requires approved fresh state |
| A | Agent framework/worker: 1–4 burst cores; 0.1–1 GB per process | No model VRAM unless local backend | 0.1–3 GB environment | Each turn/context can multiply cloud usage; avoid idle workers |
| S | Multi-service/Electron/database: 0.5–4+ GB RAM, workload-dependent CPU | 0 by default; bots/media can add GPU | 1–10+ GB plus persistent data | Idle cost and extra ownership are the main objections |
| L | Local LLM: 2–8 CPU cores or GPU; 2–8 GB host RAM | 2–6 GB for suitably quantized 1–4B model + KV; not guaranteed to fit | 1–6 GB per model, runtime extra | One lazy server; no concurrent heavyweight media model |
| G | Media/vision: 2–8 cores; 1–8+ GB host RAM | 2–8+ GB, model/workflow dependent; can exceed laptop capacity | 1–20+ GB per selected workflow | Single reserved GPU job, bounded outputs; no assumption local video generation fits |

Tokens: **T0** deterministic step uses zero model tokens (later reasoning may use tokens); **TU** UI adds no inference; **TR** selective retrieval can reduce downstream context but adds tool/schema overhead (unmeasured); **TA** agent/judge/delegation can add calls and duplicate context; **TL** local inference can replace cloud work only when quality passes; **TC** service/auth/cloud entitlement is uncertain or can bill, so block unverified egress. None is a measured savings claim.

Complexity **L/M/H** combines adapter work, version churn and long-term ownership. Security must still be evaluated per exact tool. Every selected capability must satisfy common gate B0 plus its benchmark family: MCP B1; code B2; web B3; Windows B4; memory B5; speech B6; local inference B7; documents/media B8; security B9; UI B10; optional delegation B11. These IDs are specified in the roadmap. Deferred/rejected candidates have no implementation commitment.

## Maintenance and compatibility exceptions that change priority

- Hermes advanced delegation requires a newer core; current isolated sessions intentionally have no native tools, plugins, memory or scheduler.
- Serena current main is a development version with GPL application code, a REPL interface and Pydantic 2.12.5, unlike broker 2.11.4. Isolate it and expose read-only symbols only.
- Inspector v2 requires patched Node ^22.23.4 / ^24.22.1 / >=26.12.1; current Node is 22.13.1. Playwright's current official OS floor is Windows 11, not a Windows 10 support promise.
- OpenMausBot's publisher/license evidence conflicts across endpoints and its real source/runtime identity must be reconciled. A previous Node 22 MCP catalog probe cannot satisfy its documented Node >=24 application requirement.
- Gitleaks now receives security fixes rather than new features; adequate for pinned scanning, with maintainer continuity tracked. Chatterbox is explicitly retired. UI-TARS and the old glTF samples are archives.
- Home Assistant URL is wrong in the input; Sentence Transformers, Firecrawl, Goose and FastMCP have redirected owners. Do not trust stale owner/name strings in install scripts.
- Source-available Screenpipe, Phoenix ELv2, n8n, mixed enterprise packages and per-skill/per-model terms require separate review. MIT code never establishes unrestricted hosted inference.

All other maintenance cadence remains unmeasured here. At implementation, inspect the exact release's recent commits, security policy, CI/platform matrix and unresolved blocking issues; pin SHA/artifact digest and keep rollback. Do not interpret a mature project or passing scanner as permission to enable its side effects.
