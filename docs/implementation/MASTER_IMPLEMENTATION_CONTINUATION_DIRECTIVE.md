## New finding F-38

The independent auditor identified an issue in tool-mode provider streaming.

The current audit snapshot's broker accumulates raw streamed JSON chunks and applies a 128,000-byte buffer limit.

Each token's streamed transport envelope may contribute approximately 300–460 bytes of raw JSON.

Therefore, the buffer can overflow after roughly 280–410 output tokens, despite a provider call permitting 2,048 output tokens.

The auditor reproduced the failure offline using a synthetic 600-chunk stream.

The reproduction produced:

- The same generic provider failure message.
- Unknown token usage.
- Conservative full token charging.
- Successful behavior with shorter streams.

This closely matches the historical failed live report.

**Important distinction:**

The raw-chunk-buffer overflow mechanism is reproduced.

Its role as the actual cause of the historical live failure remains a leading hypothesis, not a proven fact.

## Implement K-32 — bounded semantic streaming

Inspect the actual current code, including the provider relay in `app.py`.

Replace unsafe raw-envelope accumulation with a bounded, validated streaming representation.

Requirements:

1. Do not count repeated transport-wrapper bytes as semantic model output.
2. Do not accumulate unnecessary reasoning text.
3. Do not persist private reasoning content.
4. Keep tool-call arguments bounded by actual validated payload limits.
5. Keep a separate bounded limit for individual transport events.
6. Preserve incremental parser correctness.
7. Preserve tool-call IDs and fragment ordering.
8. Preserve supported provider finalization semantics.
9. Preserve final usage information when available.
10. Do not allow unbounded memory growth.
11. Preserve cancellation and timeouts.
12. Reject malformed and ambiguous tool calls.
13. Preserve the broker's strict capability validation.
14. Introduce a distinct `bridge_output_limit` failure category.
15. Record bounded, non-sensitive diagnostic counters.

Do not simply remove the 128 KB limit and allow unlimited buffering.

Do not drop legitimate content merely because it arrives in many small SSE fragments.
