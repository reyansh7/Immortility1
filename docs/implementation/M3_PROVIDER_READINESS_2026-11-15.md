# Provider readiness — 2026-11-15

**Production multi-provider acceptance: BLOCKED.** Existing adapters were retained. The broker's `ModelRegistry.rejection()` and `verify_dispatch()` remain separate admission and dispatch checks: internal metadata alone cannot authorize a new route. Groq, Gemini and NVIDIA remain closed even when synthetic offers pass registry fixtures. No account console, protected metadata endpoint or credential-backed inference was accessed during this work.

These are documentation observations, not findings about this user's accounts. No legal conclusion about a specific NVIDIA subscription is asserted.

The feasibility decision is deliberately explicit. OpenRouter has a documented account-quota API that can succeed after approval; it should not be replaced with guessed quotas. For other providers, this review did not establish a supported API that proves all account/model billing conditions before inference. Building a verifier that requires an undocumented response field would never produce trustworthy admission. A separately authorized, user-reviewed account-console attestation may be feasible, but its trust, freshness and revocation rules are a product decision, not an implemented permission shortcut. No attestation editor or frontend assertion was added.

The existing proof contract binds `ModelOffer` to provider/model identity, qualification, credential identity, expiring price/account timestamps, privacy, context and health. Credential rotation invalidates the old binding; tests retain this behavior. Proof timestamps are local evidence expiry, not provider guarantees. No universal safe TTL for account billing status was established. Billing plan or model pricing can change independently; future account verification must document the race and fail closed on stale/absent evidence. The preserved OpenRouter public price check remains per request; no TTL cache bypass was introduced.

Quota observations can become stale through another client immediately. Local ceilings remain **50 reservations / 100,000 charged-or-reserved tokens per provider per UTC day**, shared across credentials/tasks. They are not account allowances. Unknown usage remains charged; proved-unsent preflight cancellation releases its token reservation. Failed or unavailable manual routes never silently change provider.

Before another production route can open: verify concrete model/context/tool streaming, establish a supported account/price proof and refresh policy, bind the credential, pass deterministic transport/privacy/budget/rotation tests, present accurate UI metadata, and obtain separate bounded live acceptance authorization. If attestation cannot meet the free-only policy, record the necessary product decision and keep the route disabled. No paid fallback, account upgrade or promotional-credit assumption is permitted.
