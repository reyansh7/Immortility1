# Forward architecture constraint — latest user direction

This supersedes the earlier optional-OpenRouter fallback recommendation and the OpenRouter/OmniRoute recommendations in older directives. It does not request a restart, removal of historical evidence or rewrite of completed M3 transport/UI work.

- OpenRouter and OmniRoute are excluded from the forward architecture. Do not install, integrate, qualify, benchmark or activate either. Historical adapters, fixtures and evidence are retained; the legacy fallback gate defaults off. No further legacy-provider work is planned.
- Hermes remains the canonical intelligence, native routing/fallback and delegation harness. The existing broker independently authorizes every dispatch, protects credentials, enforces budgets and owns shared context with Engine/Store. Native fallback must never bypass these checks or silently replay a side-effecting task.
- Prioritize direct Gemini, Groq and NVIDIA transport qualification and feasible account/model-specific zero-cost proof. Existing adapters already address their official endpoints; deterministic fixtures are not production eligibility. No new API gateway, routing framework, scheduler or service.
- Qwen3.5-9B remains optional and on-demand. It is not installed or activated; no model/dependency download or inference service startup is authorized by this direction.
- Prioritize warm Hermes isolation and genuine verified model-to-tool execution, then model-independent context preservation and natural interaction. Instant/Deep/Execute/Bots describe logical behavior in the same stack, not four resident processes.

## Current effect and remaining gates

Default cloud admission is fail-closed: the legacy fallback is off and no direct production model currently has sufficient account/model/tool-call evidence. No provider was activated merely to make the UI appear ready. Existing local deterministic workflows remain available under their existing consent contracts. No live inference or protected account API was called in this slice.

The legacy quota validation was already being completed when the direction changed. Its offline fixtures are retained as security regression coverage; it is not an integration roadmap item. No new legacy benchmark or live acceptance will be requested.

Direct-provider acceptance must identify a concrete model, fresh supported zero-cost/account evidence, context limits, streaming/tool-call behavior, credential binding and separately authorized bounded live execution. If the provider cannot expose sufficient evidence, document the product decision and keep dispatch blocked. Credits, stored keys and advertising alone do not qualify.

Warm reuse is not enabled. The current launcher binds per-task loopback credentials and profile-scoped MCP state. A temporary sequential text-profile probe passed credential/history isolation and owned-process cleanup; it does not qualify tools or production reuse. The next permissible experiment must prove MCP/tool isolation, cancellation, crash recovery and idle resources. Preserve all existing task and permission deadlines.
